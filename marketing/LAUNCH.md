# Launch and first revenue path (no required upfront hosting)

## Distribution

- Firefox: add-on submission/signing through Mozilla Developer Hub. The developer account exists, but this repository has no linked Mozilla submission credentials; publishing cannot be done from GitHub alone.
- Chrome: developer registration entails a one-time fee. Prioritize Firefox while preserving Chrome package readiness.
- Current GitHub repository is private. Its pages, releases and README **are not a public distribution or customer acquisition channel** until visibility/publication changes.
- Reddit: no Reddit account publishing integration is connected. `REDDIT_POST.md` is a ready-to-post template, not a published announcement.

## Monetization sequence

1. Continue releasing free filtering without upfront hosted APIs.
2. Sign/publish Firefox and begin authentic user acquisition with transparent early-adopter messaging.
3. Connect Stripe Payment Links to receive founding-sponsor payments. A payout account must be set up by its legal owner.
4. Sell one clearly defined, one-month, direct sponsor pilot (proposed $49; price not market-validated). Don't sell impressions you cannot yet measure.
5. Approve campaign copy/destination, add it to static catalog and submit an extension update.
6. Later evaluate a hosted catalog or billing automation only if income/volume justifies ongoing infrastructure.

## Constraints

There is no automatic global creator-country service here. Unknown accounts stay unknown, and an allowed-language filter is not geographic proof. Strict unknown blocking may empty feeds. Better local language filtering can still help even when origin can't be determined. Accurate automatic Facebook account origins remain unsolved.

No paid sponsor, installed extension customer base, connected processor, or money deposited is established by writing code. These external states must be verified before claiming revenue.
